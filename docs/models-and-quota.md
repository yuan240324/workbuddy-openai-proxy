# 模型与额度

这一页讲**概念**：站点之间什么关系、额度怎么算、请求怎么路由。
具体有哪些模型见 [README 的「示例模型清单」](../README.md) —— 那一节跟着上游变，这里不重复。

---

## 一、站点（site）

一个「站点」= 一套独立的上游账号体系。当前支持：

| 站点键 | 上游 | 说明 |
|---|---|---|
| `cn-cli` | `copilot.tencent.com` | 国内版 CLI |
| `intl-cli` | `www.codebuddy.ai` | 国际版 CLI |
| `intl-work` | `www.workbuddy.ai` | 国际版 WorkBuddy |

`deepseek` 分支另有 `deepseek`（`chat.deepseek.com`，协议不同）。

**关键点：额度不通用。**

国内版和国际版是**两套独立账号、两份额度**。登录了哪边就只消耗哪边。
两边都想要就登录两次：

```bash
node login.mjs --site cn-cli
node login.mjs --site intl-cli
```

## 二、额度与倍率

每个模型有一个**积分倍率**（credits multiplier）。同一次请求，倍率高的模型扣的积分多。
控制台「模型与切换」分页会把倍率直接列出来。

> 国际版的计费口径与国内版不同：
> **同一个模型名，在两边可能一个扣费、一个不扣费。**
> README 的「国际版实测可用模型」一节记了实测单价。

**选模型的实用建议**：日常对话用倍率低的 flash / turbo 类；
需要推理或写代码时再换 pro 类。在控制台点一下切换即可 ——
客户端那边因为填的是 `default`，不用改。

## 三、请求怎么路由到站点

按下面的顺序依次判断，命中即停：

1. **显式站点前缀** —— `intl-cli/claude-sonnet-4.6` 这种写法直接指定站点，优先级最高
2. **别名映射** —— `config.json` 的 `modelAliases`（见下）
3. **显式路由表** —— `config.json` 的 `modelRoutes`，把某模型钉到某站点
4. **目录匹配** —— 多个站点都有该模型时，选**倍率最低**的（未知倍率排最后）
5. **兜底** —— `defaultSite`

### 别名（modelAliases）

把常用模型起个别名，客户端里填短的就行：

```jsonc
{
  "modelAliases": {
    "default": "intl-cli/deepseek-v4.1-flash",
    "fast":    "intl-cli/deepseek-v4.1-flash",
    "claude":  "intl-cli/claude-sonnet-4.6"
  }
}
```

> ⚠️ **`default` 别名会覆盖 `defaultModel`。**
> 如果两个地方都配了，**别名优先** —— 很容易让人以为配置没生效。
> 建议只留一处。

### 路由表（modelRoutes）

把某个模型钉死在某个站点（比如为了走国际版的免费额度）：

```jsonc
{
  "modelRoutes": {
    "deepseek-v4-pro": "cn-cli",
    "glm-5.3": "cn-cli"
  }
}
```

> 有个细节：如果目标站点的**动态目录**里明确没有这个模型，该路由会被**忽略**，
> 改为自动选站。这是为了避免内置清单不全时误判。
> （动态目录拉不到时会退回内置清单，那种情况下路由表仍然生效。）

## 四、号池（同一站点多个账号）

同一个站点可以放多个账号。选号顺序：

**没用尽的 → 失败次数少的 → 最久没用过的**

- 额度耗尽 → 标记为耗尽，**6 小时**后自动重试
- 请求失败 → 按 `0s → 30s → 2m → 10m → 30m` 阶梯冷却
- 全站耗尽 → 如果另一个站点也有这个模型，**自动降级过去**

降级时会**优先挑还有可用账号的站点**，而不是只按倍率挑 —— 只比倍率容易
从一个已耗尽的站点降级到另一个同样耗尽的站点。只有当所有候选站点都没有
可用账号时，才退回按倍率挑选（额度可能已经重置了，仍然值得试一次）。

> 只放了一个账号的站点（还没有池文件）同样会记录额度耗尽状态，只是这份状态
> **只存在内存里**：不落盘、不会因此建出池文件，重启服务即清空。
> 这样路由能避开已经 429 的站点，又不会让控制台轮询产生写入副作用。
> 重新登录换了凭证时旧状态自动失效，新账号不会被上一个号的耗尽标记连坐。

```bash
node login.mjs --site cn-cli --label 小号   # 加一个账号并起名
node login.mjs --list                      # 看号池现状
```

控制台「账号登录」分页可以逐账号查看状态、禁用、重置失败计数、改备注。

> 号池是**本机多账号轮转**，不是跨机器共享额度。
> 要多人共享请用那些自托管网关项目 —— 见 [README 的「和同类项目的区别」](../README.md#和同类项目的区别)。

## 五、模型过滤

不想让某些模型出现在列表里 / 不想被误用：

```jsonc
{
  "allowModels": ["glm-*", "deepseek-*"],   // 只允许这些（支持通配）
  "excludeModels": ["*-preview"]            // 排除这些
}
```

也可以在 `sites.<站点>` 下单独设，只对那个站点生效。
被过滤掉的模型如果被调用，服务会返回明确的 404 并说明原因，而不是含糊地报「找不到」。

## 六、查询现状

```bash
node status.mjs        # 各站点登录态 + 剩余积分
node ask.mjs --list    # 当前可用的全部模型
```

或打开控制台：

| 分页 | 看什么 |
|---|---|
| 状态总览 | 各站点登录态、剩余额度、token 到期时间 |
| 模型与切换 | 完整模型清单（含倍率、上下文窗口、所属站点），一键切换默认模型 |
| 用量统计 | 按天 / 按模型的调用量、token、积分消耗 |
| 实时日志 | 每条请求的站点、模型、状态码、耗时、首字节时间 |
